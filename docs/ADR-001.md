# ADR-001: FitFlow Technology Stack

**Status:** Accepted

## Context
FitFlow requires Android/iOS/web access, high mobile performance, native health integrations, AI features, real-time social interaction and secure wellness-data handling.

## Decision
Use Kotlin Multiplatform for shared mobile domain/data code, Jetpack Compose and SwiftUI for native mobile UIs, React/TypeScript for web, Go for main APIs, PostgreSQL for durable data, AWS Cognito for authentication, Python/FastAPI for AI, Redis for caching and WebSockets for real-time events.

## Rationale
This architecture shares code where reuse is valuable but does not force the same UI or runtime across workloads with different requirements. It gives direct access to mobile health APIs, a mature browser stack, efficient APIs and a strong Python ML ecosystem.

## Consequences
The solution requires more skills and CI/CD coordination than a single-framework application. In return, mobile fidelity, service isolation and long-term scaling are improved.
